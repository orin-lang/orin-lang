- **Process arguments, stdin, files and network on Orbit (ADR-0055 decision 9).** Programs that use `std:process` `args`, `std:io` stdin, `std:fs`, `std:path`, `std:net`, `std:http` and DNS now build for `wasm64-orbit` and `wasm32-orbit` and run unchanged on the Orbit runtime: the WebAssembly L0 maps them onto `orbit:process/v1`, `orbit:fs/v1` and `orbit:net/v1`, and the host grant (`--app-arg`, `--grant process:stdin`, `--grant fs:/data=./dir:rw`, `--listen`, `--grant net:connect=...`) decides what they may reach. The manifest lists the new capabilities (`process/v1`, `fs/v1`, `net/v1`) and the generated C includes the matching L0 family, so a module imports exactly what it lists. E0523 now only reports `Process.Spawn` (the shell). A stdout line written in several `writeStdout` calls is one log record. One WebAssembly thread still runs every task, so a server serves one connection at a time and a blocked `accept` ends by its timeout; there is no environment, mkdir, remove or rename yet. `tools/test_orbit.py` and `tools/run_tests.py --orbit` run the programs on the real Orbit (skipped without it); `tools/wasm_run.mjs` serves `process/v1` and `fs/v1` for CI.
