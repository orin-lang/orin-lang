- **Contract verifier: recursive records, classes and unions (ADR-0053 Addendum A).** `orin verify --contracts` gave UNKNOWN for every clause that read or wrote a field of a type that reaches itself ("the fields of the recursive type `FnCtx` are not modelled"), built a variant of a recursive union, or matched on one. Such a type now has an uninterpreted sort with an accessor function per field (a union: a variant tag and payload accessors); a value built in the code is a fresh constant with its fields as facts (no quantified axiom), so field reads and writes, record literals, variant construction, `match` and the frame facts of mutating methods are reasoned about like those of any other record, class or union (value semantics, A-INV and A-FRAME as before). Because a model of the solver need not be a finite value, a function that uses a recursive type never gets a counterexample: a wrong claim stays UNKNOWN, never VERIFIED. In such a function the bounded-search retry, the unrolled-loop pass and the per-path re-solve (which only ever look for a counterexample) are skipped. Regression test: `tests/contracts/verify_rectypes.or`.
